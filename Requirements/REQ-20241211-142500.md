# Requirement Document: Compound Interest Calculator

## 1. Overview

The Compound Interest Calculator is a single-page web application that enables users to calculate compound interest projections with optional recurring contributions. The application provides real-time calculations, interactive data visualization, and detailed year-by-year breakdown analysis. The system is designed as a client-side application requiring no backend services, delivering immediate calculation results with visual feedback through charts and animated displays.

## 2. Functional Requirements

### 2.1 Input Management
- **FR-001**: The system shall accept principal amount input with minimum value of $0.01
- **FR-002**: The system shall accept annual interest rate input between 0% and 100%
- **FR-003**: The system shall provide compounding frequency selection (daily, weekly, monthly, quarterly, semi-annually, annually)
- **FR-004**: The system shall support duration input with toggleable units (years/months)
- **FR-005**: The system shall accept optional monthly contribution amount (minimum $0)

### 2.2 Calculation Engine
- **FR-006**: The system shall calculate compound interest using the standard compound interest formula: A = P(1 + r/n)^(nt) + PMT(((1 + r/n)^(nt) - 1) / (r/n))
- **FR-007**: The system shall generate year-by-year progression data showing starting balance, contributions, interest earned, and ending balance
- **FR-008**: The system shall handle partial year calculations for duration inputs
- **FR-009**: The system shall separate total principal (initial + contributions) from interest earned
- **FR-010**: The system shall trigger calculations automatically upon input changes with 300ms debounce

### 2.3 Data Visualization
- **FR-011**: The system shall render an interactive area chart showing principal and interest growth over time
- **FR-012**: The system shall display chart tooltips on mouse hover showing year and balance information
- **FR-013**: The system shall implement dynamic chart scaling based on calculated maximum values
- **FR-014**: The system shall provide animated value transitions for final balance display

### 2.4 Results Display
- **FR-015**: The system shall display final balance with animated number formatting
- **FR-016**: The system shall show total principal invested and total interest earned
- **FR-017**: The system shall provide toggleable detailed breakdown table with year-by-year data
- **FR-018**: The system shall format currency values with locale-specific formatting
- **FR-019**: The system shall display large numbers with K/M suffixes for compact representation

### 2.5 Validation & Error Handling
- **FR-020**: The system shall validate all input fields in real-time
- **FR-021**: The system shall display error messages for invalid inputs
- **FR-022**: The system shall prevent calculation when validation errors exist
- **FR-023**: The system shall provide clear error indication for out-of-range values

### 2.6 User Interface
- **FR-024**: The system shall provide unit toggle between years and months for duration input
- **FR-025**: The system shall implement smooth CSS animations for UI state changes
- **FR-026**: The system shall maintain responsive design for various screen sizes
- **FR-027**: The system shall provide show/hide functionality for detailed breakdown section

## 3. Non-Functional Requirements

### 3.1 Performance
- **NFR-001**: The system shall perform calculations and update displays within 100ms of input change
- **NFR-002**: The system shall render charts smoothly without blocking user interface
- **NFR-003**: The system shall implement debounced calculation triggers to optimize performance
- **NFR-004**: The system shall handle calculations for duration periods up to reasonable limits without performance degradation

### 3.2 Usability
- **NFR-005**: The system shall provide immediate visual feedback for all user interactions
- **NFR-006**: The system shall use clear, readable typography with Google Fonts integration
- **NFR-007**: The system shall implement intuitive form controls with appropriate input types
- **NFR-008**: The system shall provide smooth animations that enhance user experience without distraction

### 3.3 Compatibility
- **NFR-009**: The system shall function in modern web browsers supporting HTML5 Canvas
- **NFR-010**: The system shall work offline after initial load (no server dependencies)
- **NFR-011**: The system shall support locale-specific number formatting
- **NFR-012**: The system shall render correctly across different viewport sizes

### 3.4 Reliability
- **NFR-013**: The system shall handle edge cases in mathematical calculations gracefully
- **NFR-014**: The system shall prevent calculation errors through robust input validation
- **NFR-015**: The system shall maintain calculation accuracy for all supported input ranges

## 4. Data Requirements

### 4.1 Input Data Structure
- **DR-001**: Principal amount (decimal, minimum 0.01, maximum reasonable investment amount)
- **DR-002**: Annual interest rate (decimal, range 0-100, precision to 2 decimal places)
- **DR-003**: Compounding frequency (enumerated: 365, 52, 12, 4, 2, 1)
- **DR-004**: Duration value (integer, positive values only)
- **DR-005**: Duration unit (enumerated: 'years', 'months')
- **DR-006**: Monthly contribution (decimal, minimum 0, optional)

### 4.2 Calculation Data Structure
- **DR-007**: Chart data array containing year, balance, and principal values for each period
- **DR-008**: Breakdown table rows with year, start balance, contributions, interest, and end balance
- **DR-009**: Summary statistics including final balance, total principal, and interest earned

### 4.3 UI State Data
- **DR-010**: Form validation states for each input field
- **DR-011**: Current unit selection state (years/months)
- **DR-012**: Breakdown table visibility state
- **DR-013**: Chart interaction metadata for mouse position calculations

### 4.4 Display Data Formatting
- **DR-014**: Currency formatting with locale-specific symbols and separators
- **DR-015**: Percentage formatting for interest rates
- **DR-016**: Compact number formatting with K/M suffixes for large values

## 5. Integration Requirements

### 5.1 External Dependencies
- **IR-001**: The system shall integrate with Google Fonts API for DM Serif Display, DM Mono, and DM Sans typefaces
- **IR-002**: The system shall utilize browser Canvas 2D Context API for chart rendering
- **IR-003**: The system shall use DOM manipulation APIs for dynamic content updates

### 5.2 Browser APIs
- **IR-004**: The system shall leverage CSS Animation APIs for smooth transitions
- **IR-005**: The system shall use JavaScript timing functions for debounced calculations
- **IR-006**: The system shall implement mouse event handling for chart interactivity

### 5.3 Client-Side Architecture
- **IR-007**: The system shall operate as a standalone client-side application
- **IR-008**: The system shall require no server-side processing or database connections
- **IR-009**: The system shall maintain all state in browser memory during session

## 6. Assumptions & Constraints

### 6.1 Assumptions
- **ASM-001**: Users have basic understanding of compound interest concepts
- **ASM-002**: Modern web browsers with JavaScript enabled are used
- **ASM-003**: Internet connection available for initial font loading
- **ASM-004**: Users input realistic investment scenarios within reasonable ranges
- **ASM-005**: Calculation accuracy requirements align with standard financial calculator precision

### 6.2 Constraints
- **CON-001**: Single-file application architecture limits modularity
- **CON-002**: Client-side only implementation restricts data persistence
- **CON-003**: Canvas-based charting requires manual implementation of interactive features
- **CON-004**: No user account management or saved calculation history
- **CON-005**: Limited to compound interest calculations (no complex investment scenarios)

### 6.3 Technical Limitations
- **CON-006**: Browser canvas size limitations may affect chart rendering for extreme data ranges
- **CON-007**: JavaScript number precision limitations for very large calculations
- **CON-008**: No accessibility features implemented for screen readers or keyboard navigation
